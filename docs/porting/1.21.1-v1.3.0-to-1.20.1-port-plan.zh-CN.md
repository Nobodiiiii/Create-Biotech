# 1.21.1 v1.3.0 到 1.20.1 移植方案

## 目标

把 1.21.1 分支自 `0dc6bbc8`（v1.2.6 之后）到 `b715b1f8`（v1.3.0）之间的全部改动，按功能单位移植到 1.20.1。
上游该区间共 60 个提交、203 个文件、约 9,600 增 1,450 删。本方案按功能分批，不按提交分批，
因为上游单个提交经常同时包含新功能、重构和修复。

移植目标是行为一致，不是文件一致。NeoForge / Java 21 / 1.21 数据组件、编解码器、
数据驱动附魔等 API 一律按 1.20.1 Forge 语义重写。

## 基线与约束

- 源分支：`1.21.1` @ `b715b1f8`，对比基线 `0dc6bbc8`。
- 目标分支：`port/1.20.1-v1.3.0`，基于 `1.20.1` @ `f8769139`。
- 目标环境：Minecraft 1.20.1、Forge 47.1.33、Create 6.0.8-291、Flywheel 1.0.5、JEI 15.48.0.183、Java 17。
- 参考环境：Minecraft 1.21.1、NeoForge、Create 6.0.10-281、Java 21。
- 第三方行为优先查 `ref/1.20.1/`，其次 `ref/1.21.1/`，按 `ref/SOURCES.md` 判断版本 caveat。
- 每批完成后执行 `./gradlew compileJava`，通过后再提交；涉及 Mixin 的批次另外检查生成的 refmap。

## 已在 1.20.1 完成的部分

`1.20.1` 分支上的 `bb0ac17a`、`f8769139` 已经先行移植了本区间的两小块内容，本方案在对应批次里只补差异，不重复实现：

- `MimicProfile` 的数据结构与培养皿写入。
- `BlockCenteredRenderedLivingEntityItem` / `BlockCenteredRenderedLivingEntityItemRenderer` 与其物品模型。

## API 差异对照

| 上游（1.21.1 / NeoForge） | 本分支（1.20.1 / Forge） |
| --- | --- |
| `DataComponents` / `DataComponentType` | `CBItemData` 包装的 `CompoundTag` NBT |
| Catnip `CatnipPacketRegistry` + `StreamCodec` | `SimpleChannel` + `FriendlyByteBuf` |
| `RegistryFriendlyByteBuf` | `FriendlyByteBuf` |
| `VertexConsumer#addVertex/setColor/setUv` | `vertex/color/uv/overlayCoords/uv2/normal/endVertex` |
| `EntityDimensions#width()/height()` | `EntityDimensions.width` / `.height` 字段 |
| `DeltaTracker` | `Minecraft#getPartialTick()` 与 `net.minecraft.client.Timer` |
| 数据驱动 `enchantment/*.json` | 代码注册 `Enchantment` 子类 + `EnchantmentCategory` |
| `tags/enchantment/treasure.json` | `Enchantment#isTreasureOnly()` |
| `tags/item/enchantable/*.json` | `Enchantment#canEnchant(ItemStack)` |
| `neoforge/loot_modifiers/global_loot_modifiers.json` | `forge/loot_modifiers/global_loot_modifiers.json` |
| `enumextensions.json` 扩展 `ArmPose` | Forge `HumanoidModel.ArmPose.create(...)`（`IExtensibleEnum`） |
| `recipe/` `loot_table/` `tags/item/` | `recipes/` `loot_tables/` `tags/items/` |
| Codec 化 `RecipeSerializer` | 1.20.1 `fromJson(ResourceLocation, JsonObject)` 序列化器 |
| `ParticleOptions` + `MapCodec`/`StreamCodec` | `ParticleType` + `Codec` + `ParticleOptions.Deserializer` |
| `neoforge.mods.toml` | `mods.toml` |

## 批次划分与执行顺序

批次按依赖排序：共享渲染基础设施最先，具体功能其次，纯数据与文案收尾。

### 批次 1：共享实体渲染基础设施

新增 `CachedRenderEntity`、`EntityGeometry`、`GuiEntityItemElement`，并把现有渲染路径迁移过去：
`RenderedLivingEntityItemRenderer`、`BlockCenteredRenderedLivingEntityItemRenderer`、`EntityRenderHelper`、
`OversizedBlockItemRenderer`、`GuiEntityElement`、`CapturedSmallSlimeItem`，
新增 `SpawnableRenderedLivingEntityItem` 与 `BlockCenteredSpawnableRenderedLivingEntityItem`。

`VertexConsumer` 的收集器按 1.20.1 接口重写；实体边界改为按模型实际顶点测量。

提交：`port(1.20): 抽取共享实体渲染基础设施`。

### 批次 2：生物纸箱图标烘焙与缓存

新增 `BakedCapturedEntityIcon`、`CapturedEntityRenderManager`、`CapturedEntityRenderTime`，
改写 `CapturedEntityBoxIconRenderer`、`CapturedEntityBoxHelper`、`CapturedEntityBoxItemRenderer`、
`CardboardBoxEntityRenderer`，新增客户端配置 `renderCapturedEntitiesOnBoxes`。

烘焙期固定 partial tick 的 `DeltaTrackerTimerMixin` 按 1.20.1 的 `Timer` 目标重写。

提交：`port(1.20): 烘焙并缓存纸箱生物图标`。

### 批次 3：JEI 场景粒子与实体预览统一

新增 `JeiSceneParticles`，合并 `AnimatedSquidSpout`、`AnimatedEvokerEnchanting`、`AnimatedKineticsWithEntities`
各自的 buffer/camera/粒子代码；`HighPressureCreeperDrawable`、`SlimeEntityDrawable`、`SquidJeiRenderer`、
`CuteCatOnShaftJeiRenderer`、`CapturedEntityBoxJeiRenderer` 改用 `CachedRenderEntity` 与统一场景变换。

提交：`port(1.20): 统一 JEI 实体与粒子场景`。

### 批次 4：鱿鱼打印机墨水粒子

新增 `SquidPrinterInkParticleOption` 与客户端 `SquidPrinterInkParticle`，
让两股墨水各自计算 `fallLimit`，在机器下方同一深度消失。

提交：`port(1.20): 对齐鱿鱼打印机墨水下落深度`。

### 批次 5：拟态细节补全与史莱姆透明层绘制顺序

在已有 `MimicProfile` 基础上补齐上游后续新增的品种字段，
并按上游调整 `SlimeMimicRenderLayer` 的内部实体/内部胶体/外层胶体绘制顺序与 RenderType 归属。

提交：`port(1.20): 补全拟态外观品种与透明层绘制顺序`。

### 批次 6：岩浆怪燃烧室（前置功能 + 重做）

1.20.1 完全没有该功能，按用户确认直接移植 1.21.1 HEAD 的重做形态：
空/已捕获拆分、默认 `HeatLevel.NONE`、空状态不建方块实体、按储量绘制熔岩液面、
固定实体加跳跃压缩动画、点火与落地粒子、新碰撞体与状态模型、燃烧贴图动画、
`getCloneItemStack` 区分掉落物品、空燃烧室配方。

同批接入 registry（方块/方块实体/物品/创造标签）与客户端渲染注册。

提交：`port(1.20): 移植岩浆怪燃烧室`（可拆为核心 + 资源两个提交）。

### 批次 7：手动物品应用的物品态语义

`ManualItemApplicationOrientationHandler` 改为先用 `getCloneItemStack` 求被点击方块的真实物品态再匹配配方；
同方块转换改为用真实 `BlockPlaceContext` 求输出状态，只继承 `FACING` / `AXIS` 等方向属性。
配套新增 `blaze_burner_manual_only` 与 `magma_cube_burner_manual_only` 配方。

提交：`port(1.20): 按物品态匹配手动物品应用`。

### 批次 8：叮咚鸡与实体红石源

新增 `dingdongchicken` 包（实体、模型、渲染器、物品、生成蛋、转化处理、语音包音效包）、
`EntityRedstoneIndex` 与 `EntityRedstoneLevelAccess`，以及接入原版信号求值的三个 Mixin。
Alternate Current 兼容按 1.20.1 该模组的 API 重写，保持独立 mixin 配置和运行时类存在检查，
构建脚本以 `compileOnly` 引入。

提交：拆为 `port(1.20): 新增实体红石源索引` 与 `port(1.20): 新增叮咚鸡`。

### 批次 9：大狗音波炮核心

`SonicDogCannonItem`、`SonicDogConeWave`、`SonicDogCannonKnockback`、`SonicDogCannonStunEffect`、
`SonicDogCannonStunHandler`、`SonicDogCannonUpgrade`、`SonicDogCannonUpgradeRecipe` 及三个客户端包。
蓄力/耐久/背罐供能、扳手拆除、升级顺序与项圈颜色改用 `CBItemData` NBT 存储。
Cataclysm 存在时复用其 stun，否则使用自带眩晕效果。

提交：`port(1.20): 新增大狗音波炮核心`。

### 批次 10：大狗音波炮客户端与附魔

物品渲染器、双手持姿势（Forge `ArmPose.create`）、蓄力/发射音效、锥形声波粒子、tooltip、
JEI 升级展示，以及 `Sonic Boom` 附魔的代码注册与远古城市战利品注入（Forge 全局战利品修改器）。

提交：`port(1.20): 新增音波炮客户端表现与音爆附魔`。

### 批次 11：悦灵物流可靠性与渲染统一

悦灵驿站向下输出改为完整模拟插入后再取出，真实插入有余量时回滚或掉落；
向下拉取删除重复模拟并取消 `PackagerItemHandler` 特判。
删除 `AllayCourierItemRenderer`，改用通用 `BlockCenteredRenderedLivingEntityItem`。
修正悦灵驿站 Ponder 英文导出里误留的中文段落。

提交：`port(1.20): 加固悦灵驿站包裹搬运`。

### 批次 12：配方、文案与工程清理

纸箱切割产量翻倍、创造模式排列、纸箱分类改名、无线终端文案精简、新功能中英文本；
`CBBeltChainData` 迁到 `foundation.block`；`LaunchedItemForBeltMixin` 去掉对 Create 内部字段的 `@Shadow`，
数组复制统一为 `Arrays.copyOf`。

提交：拆为 `port(1.20): 调整配方产量与本地化文案` 与 `refactor(1.20): 降低传送带 Mixin 映射脆弱性`。

## 不移植内容

- **巨蛙相关改动**（`GiantFrogItemRenderer` 迁移到 `GuiEntityItemElement`，4 增 28 删）。
  1.20.1 没有 `giantfrog`（1,544 行），且它依赖整个 `frogportal` 自定义维度系统（13 个文件）。
  经确认跳过；此项为已知缺口。
- 1.21 专用构建配置：NeoForge / ModDevGradle 1.21 参数、Java 21、`neoforge.mods.toml` 结构变化、
  `enumextensions.json` 文件本身。
- 只改版本号与 1.21 依赖范围的元数据变更；本分支版本号按自身节奏更新。
- `.ponderer-export/manifest.json` 中属于 1.21 导出工具链的条目，只同步与移植内容相关的文本修正。
- `art/` 目录下的 Blockbench 工程源文件按需引入：实际参与构建的模型与贴图移植，
  纯设计源文件（`.bbmodel`）只在对应功能批次里一并带上。

## 验证策略

每批：

1. `git diff --check`。
2. `./gradlew compileJava`（必要时 `--offline`）。
3. Mixin 批次检查 `build/mixin/create_biotech.refmap.json` 是否含新目标。
4. 提交前在本文件「执行记录」追加实际验证结果与遗留 caveat。

不为非 Mixin 批次运行客户端启动检查。
