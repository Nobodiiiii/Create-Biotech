# 1.20.1 维护分支回移建议

> 核对日期：2026-11-17。本文是建议清单，尚未实施回移或进行运行验证。
>
> 目标基线：本地 `1.20.1` @ `ff9b18ac`，模组版本 `1.3.0`。来源基线：`1.21.1` @ `76e33878` 及该提交中的 `CHANGELOG.md`。
>
> 当前 `gradle.properties` 仍为 `2.0.0-beta.3`；changelog 的 `2.0.0-beta.4` 节与爆破室并行渲染修复均已提交到 `76e33878`。beta.4 仍按待发布条目处理，不据此认定已发布；爆破室修复已纳入 M14。

## 1. 建议结论与维护边界

建议先发一轮以**物流库存正确性、蜘蛛组装台补料等待、纸箱渲染配置保护、旧操作说明纠正、爆破室渲染线程隔离**为核心的维护更新。随后处理纸箱捕捉关系、热气球读档同步及经验系统；蜘蛛组装台机壳、鱿鱼打印机自定义规则及其他局部优化进入独立补充批次。

“仅维护”按以下边界执行：

- 修复和优化 1.20.1 已有机器、物品和交互；允许局部的外观定制、配方规则开放、信息展示和既有 Create 接口适配，不以 changelog 标为“新增”就直接排除。
- 保持现有注册 ID、存档入口与依赖基线；局部功能必要的新配方类型或显示源注册可以增量加入，但不要求玩家为普通维护更新安装新的必需前置。
- 不追齐 2.0 功能，不整批搬入手术、仿生特性、捕捉网或新的通用扩展体系。小优化按是否局限旧模块、是否独立可用、是否兼容旧数据、是否避免新增必需依赖来判断。
- 修复所需的 NBT 新字段可以增量加入，但旧数据必须可读；涉及数值经济的默认值变化单独决定，不能夹在防丢失修复里发布。
- 按行为提取补丁。来源提交经常同时包含新功能与修复，本文给出的 SHA 是定位线索，不是整笔 cherry-pick 清单。

## 4. 各项建议与验收要点

### M01：悦灵驿站自动化与保存

**缺口与来源：**旧版 `com/yision/allay/block/allayport/AllayPortDispatchAccess.java#getItemHandler` 无论方向都返回组合库存；自动化包装器对空地址没有单独排除；`AllayPortInventory` 的载体槽没有 `onContentsChanged` 通知。来源 `04ef33d6` 已分别修正这三处，对应当前 `content/allay/block/allayport/` 下的同名文件。

**回移范围：**保持旧 `com.yision.allay` 包名，只移植方向路由、空地址判断及脏标记：上下方向使用包裹自动化处理器，水平方向使用载体槽，无方向查询保留组合处理器。不要顺带迁移悦灵模块包名或新注册组织。

**验收：**六个方向和无方向能力查询；空 / 空白 / 匹配 / 不匹配地址；模拟插入与真实插入；载体自动化增减后卸载并重载区块。包裹和载体数量应守恒，模拟查询不改变库存。发布说明需要告知方向规则被纠正。

### M02：蜘蛛组装台缺料等待

**缺口与来源：**旧版 `content/spiderassemblytable/SpiderAssemblyTableBlockEntity.java` 在 `startProcessFor` 失败后直接返回 `PASS`。来源 `a1f9ecf2` 增加缺料等待，`7433aced` 再补齐物品 / 流体锁、流体不足量和容量约束；两者应按最终行为合并回移。

**回移范围：**仅在下一步确实需要可补充的机械手或注液器时留住工件。错误锁定、不相关配方、不可能容纳所需流体等情况不能无条件 `HOLD`。本补丁不以 `SpiderProcessController` / `SpiderProcessPlanner` 拆分类重构为前置；机壳功能纳入 M12 单独实施，不与等待状态机绑成同一补丁。

**1.20 接口依据：**`ref/1.20.1/Create/src/main/java/com/simibubi/create/content/processing/sequenced/SequencedAssemblyRecipe.java#getRecipes` 返回 `Stream<R>`，不是新版带额外过滤参数的列表；应使用旧接口的流过滤。`content/fluids/transfer/FillingRecipe.java#getRequiredFluid` 返回 `FluidIngredient`，类型匹配使用 `test`，数量读取 `foundation/fluid/FluidIngredient.java#getRequiredAmount`，不能复制 `SizedFluidIngredient` / `recipe.value()`。

**验收：**空机械手、正确但不足量的流体等待补料并恢复；错误物品锁、错误流体锁、超容量配方不会永久扣住工件；原有压印和切割步骤正常放行，过程中不重复消费原料。

### M03：纸箱客户端配置加载保护

**缺口与来源：**旧版 `CapturedEntityBoxItemRenderer` 等路径直接调用 `CLIENT.renderCapturedEntitiesOnBoxes.get()`。来源 `7e31da95` 在 `registry/CBConfigs.java` 引入 `shouldRenderCapturedEntitiesOnBoxes()`，以 `CLIENT_SPEC.isLoaded()` 保护启动期渲染查询，并更新纸箱、JEI 和缓存调用点。

**回移范围：**为旧版 ForgeConfigSpec 增加同等安全入口，并搜索、替换旧纸箱路径中的直接读取。未加载时使用普通纸箱显示；加载后遵守配置。黄油食物属性的服务端配置保护已经存在，不再重做，也不搬入仿生 JEI 查询或新缓存架构。

**验收：**资源加载和物品预览不提前读取未加载配置；开关关闭后物品、JEI、世界纸箱均回到普通纸箱显示，实体图标任务不继续累积。

### M04：音波汪汪炮操作说明

**缺口与来源：**旧版 `SonicDogCannonItem.use` 已要求主手使用、玩家潜行且副手持扳手，但语言键 `item.create_biotech.sonic_dog_cannon.tooltip.condition2` 只写“副手手持扳手时右击”。来源 `42ff5d47` 已修正中英文说明。

**回移范围与验收：**只修改 `assets/create_biotech/lang/zh_cn.json` 和 `en_us.json` 对应文案，明确“潜行右击”。校验 JSON、键名和实际操作一致，无需新机制或新网络包。

### M05：纸箱捕捉的关系清理

**缺口与来源：**旧版 `content/cardboardbox/CapturedEntityBoxHelper.captureEntity` 直接保存实体 NBT，没有来源 `cbcf4af6` 中的 `detachForCapture`。后者使用正常下坐骑、驱散乘客和解除拴绳流程，并检查关系是否仍存在。

**回移范围：**只修复现有大小纸箱的捕捉入口，服务端完成关系处理后再记录数据和移除目标。注册 ID、目标资格等前置检查应尽量在解除关系前完成。下坐骑被否决时捕捉失败，不强制绕过事件；不消耗纸箱、不删除实体。不要带入捕捉网、仿生事件和手术台专用逻辑，也不要把新版本 `EmptyCardboardBoxItem` 的类判定直接复制到旧物品体系。

**验收：**目标正在骑乘、目标载有玩家或其他乘客、目标被拴住、其他模组否决下坐骑；成功后只捕捉目标，其他实体保留在世界，释放后无悬空关系。失败时实体与物品数量守恒；多步解除操作若中途被否决，应明确哪些关系已经解除，不能承诺自动回滚一切。

### M06：热气球装配站红石状态

**缺口与来源：**`39a71921` 在 `GhastHotAirBalloonAssemblyStationBlock` 增加 `POWERED`，放置时采样红石，并在对应方块实体 `onLoad` 时重新同步。这属于已有机器生命周期修复，可以脱离该提交中的思索和无线终端改动。

**回移范围：**先对照旧版装配 / 拆卸边沿状态机，再移植放置和重载同步。新增 `POWERED` 默认值时同时维护 blockstate 资源，确保旧存档中只有朝向的状态仍可加载。不能把“纠正显示状态”和“重新触发一次装配”混为一谈。

**验收：**有电 / 无电放置；有电保存并重载；断电保存并重载；连续红石切换。没有重复装配、无故拆卸、残留座椅或恶魂引用，旧装配站可继续使用。

### M07：经验泵与经验母岩，作为独立批次

**缺口与来源：**来源 `cbcf4af6` 和 [经验系统说明](../experience-system.zh-CN.md)。旧泵 `drainItemInput` 使用 `missing / xpPerItem` 向下取整，额度不足一个物品时会跳过；这并不能直接证明旧泵已经“吞掉整件物品的多余经验”。旧母岩 `applyFluidToFace` 则确实将累计输入钳制在成熟阈值，同时返回已接收全部输入，存在多余灌注不被保留的缺口。

建议拆成三个可审阅部分：

1. **泵缓存与管网适配。**引入持久化的整件物品吸收余量，让低速也能逐步使用高经验物品；模拟抽取不扣缓存，堵塞时缓存有界增长并停止继续吸收。保持 Create 原生压力、分流、反向与堵塞语义，不在 tick 中反复替换连接对象。
2. **母岩溢出与旧数据读取。**按面保存溢出、收获后保留该面已支付余量，确保输入、产出和保存数据守恒。旧 `Face0..Face5` 缺少新字段时能安全加载，转换只在加载时执行，当前格式走快路径。
3. **默认数值是否调整，单独决定。**旧版四阶段为 `16 / 32 / 64 / 128`，新版为 `24 / 48 / 96 / 192`。后者用于对齐默认粉碎产出，但也改变现有生产线的灌注成本。若不在本轮维护中调整，应明确旧默认经济关系仍保留；若调整，必须配套进度换算、旧默认配置的一次性迁移与自定义配置保留，不能只改四个数字。

**风险控制：**母岩只保留余量而不处理旧默认经济关系，并不等于整个经验循环已经守恒。泵、母岩和粉碎配方需要一起核算；按内容拆提交，但完成这一组验证后再决定是否发布。缺少验证时间时，整批后移，不拖延前述小修。

**适配依据：**优先查 `ref/1.20.1/Create/src/main/java/com/simibubi/create/content/fluids/pump/PumpBlockEntity.java`、流体包中的 `FluidTransportBehaviour.java`、`PipeConnection.java` 和 `FluidNetwork.java`。来源的 `mixin/PipeConnectionAccessor.java` 访问 `source` / `network`，字段描述符均擦除为 `java.util.Optional`，没有映射的 Minecraft 类型；这是可逐项核实 `remap = false` 的候选，不应与带 Minecraft 描述符的注入混为一谈。目标参考中存在同名同类型字段，实施时仍须检查旧工具链编译和实际注入结果。

**验收：**低速输入高价值物品、储罐直连、多分支、堵塞 / 解堵、开放出口、反转、模拟抽取、缓存重载；母岩六面独立、手动收获、连续过量灌注、旧阶段进度、自定义数值。核算消耗的 XP、库存 / 缓存余额和产出，扣除自然免费生长后再比较，不能以“看起来能流动”代替守恒检查。
