# 手术台拟态生物：原版生物能力与 cube 素材总表

**状态：** 供实现与平衡讨论使用的首版总表。适用基线为 Minecraft 1.21.1、NeoForge 21.1.234、Create 6.0.10-281；手术台的 cube 编号、来源模型和组件保存方式以 [切分系统设计](specs/2026-08-23-surgical-dissection-system-design.zh-CN.md) 为准。

## 1. 规则与记法

这不是“换成某生物外观就自动取得它全部 AI”的设计。能力只由装配体中仍存在的、来自指定原版生物模型的 cube 组解锁；同一能力可由多个同类来源组满足，能力效果不随重复素材叠加，除非另有标注。来源生物的 AI、装备、库存、驯服/交易状态和 boss 逻辑一律不继承。

模型 cube 的全局整数编号会在资源重载、模型层和版本变化时重新枚举，不能写进内容表。下表的“cube 组”是**同一来源实体**中按渲染模型路径归类的可辨识子树；实现时应在客户端把 cube 的稳定 `ModelPart` 路径和范围写入 `SurgicalAssembly` 的能力素材快照，而不是硬编码 cube id。

| 记法 | 选择规则 |
| --- | --- |
| `头` / `躯干` | 对应模型根部中头部或主体的完整可见 cube 子树；不含装饰性独立层。 |
| `前肢×2`、`后肢×2` | 左右对应肢体子树均完整；四足动物的“腿”按前/后两对区分。 |
| `翼×2`、`尾`、`壳`、`刺` | 对应左右翼、尾、甲壳或攻击性附属物的完整子树；多段结构须保留全部段。 |
| `核心` | 生物最主要的躯干/头部主体 cube 组；用于避免把一个小装饰件变成完整超能力。 |
| `任一完整来源组` | 该组必须来自同一个被捕获实体，不能用不同来源的半组拼凑。 |
| `—` | 该生物不提供能力；其 cube 仍可用于造型、碰撞体积或其他非能力系统。 |

### 通用触发与冲突规则

- 被动能力只在拟态仿生体存活、装配体仍保留所需 cube 组时生效；失去任一必需组立即失效。
- 主动能力由“使用/攻击”键触发，默认冷却 6–20 秒；所有远程、爆炸、传送与召唤效果必须只由服务端判定与生成。
- 同类抗性取最高档，不相加：`火焰免疫 > 火焰抗性`，`水下呼吸 > 水下活动加成`，`摔落免疫 > 摔落减伤`。
- `核心` 不能充当其他部位的替代品；例如有烈焰人躯干但没有杆臂，不能获得火球。
- 变种（如猫花色、马毛色、热带鱼花纹）默认只影响外观；表中明确写出变种差异的才影响能力。
- 高破坏性/首领能力标记为“受限”：需要额外配置开关，且应受 mobGriefing、PVP、区块保护与实体上限约束。

## 5. 实现优先级与数据结构建议

建议分三期落地，避免第一版把每种原版攻击都带入网络与区块保护风险。

1. **第一期（纯被动）：** 缓降、弹跳、奔跑、攀墙、水下呼吸/游泳、火焰抗性、摔落减伤、墨幕、荆棘甲、蜷缩防御、幽匿感知。它们不生成破坏性投射物，且最能体现“用 cube 拼身体”。
2. **第二期（受控主动）：** 撞角、蹄击、撕咬、毒咬、雪球、普通箭、三叉戟、短距传送、潜影弹、守卫者激光、俯冲、蛛网陷阱。全部经由服务端冷却、目标合法性和实体数上限校验。
3. **第三期（配置默认关闭）：** 火球、爆裂、唤魔者尖牙、音爆、凋灵头颅、龙息与所有首领强度升级。必须同时检查 `mobGriefing`、领地/权限 API、PVP 和发射物归属。

推荐把能力快照放在独立的、服务端可验证的数据对象中，而不是每 tick 扫描客户端 cube：

```text
MimicAbilityMaterial {
  sourceProfileKey: UUID / source index
  modelSignature: resource reload-sensitive hash
  groups: set<BodyGroup>          // HEAD, CORE, LEFT_WING, RIGHT_WING ...
  variantFlags: set<VariantFlag>  // CHARGED_CREEPER、ELDER_GUARDIAN 等极少数例外
}

ResolvedMimicAbility {
  id: ResourceLocation
  sourceProfileKey
  requiredGroups
  cooldownEnd
}
```

`BodyGroup` 应由客户端模型采样阶段按模型路径产生，并连同 cube 集合一并进入装配体；服务端只接受已保存装配体中“完整组仍存在”的结论。组合能力必须比较同一 `sourceProfileKey`，因此不会出现“左翼来自鹦鹉、右翼来自烈焰人却解锁飞行”的歧义。

## 6. 验收示例

- 保留一只鸡的两翼 cube 组：仿生体获得缓降；切掉任意一侧翼组后立刻失效。
- 保留一只山羊的头角、躯干和四腿：获得撞角；只有角而没有四腿时没有能力。
- 将守卫者的核心、刺和眼完整装入同一组件：解锁激光；缺少眼或刺只保留荆棘甲（若刺组完整）。
- 由两只不同生物分别提供一侧翅膀：不解锁任何需要“翼×2”的能力。
- 不开启首领能力配置时，末影龙、凋灵、带电苦力怕仍能被切分、组装与渲染，但其受限主动能力绝不注册。
