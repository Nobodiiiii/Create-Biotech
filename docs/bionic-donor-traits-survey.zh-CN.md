# 手术台供体基础特性调研（Minecraft 1.21.1）

调研日期：2026-09-18。依据本分支的 Minecraft `1.21.1`、NeoForge `21.1.234`、Create `6.0.10-281`。

本文同时保留设计调研与实现边界。全体块体质现已实现自动探测、按保留体块占比汇总、纸箱属性展示及仿生生物执行；头部、运动器官、攻击器官与防御姿态仍是后续设计。表中的**来源生物与原版行为**来自当前版本源码；**承载部位、装配后的效果与合并规则**是本模组规则，原版没有器官移植规则。

推荐采用：**通用探测器读取供体事实 → 数据规则修正生物族与个体 → 解剖部位筛选 → 装配结果汇总 → 仿生生物执行能力**。这样能自动覆盖遵循原版接口和标签的模组生物，并允许整合包对例外逐项调整。

## 适配等级与部位约定

| 标记 | 读取方式 | 适配边界 |
| --- | --- | --- |
| A | 实体类型属性、原版实体类型标签 | 无需构造实体，优先使用。模组正确注册属性/标签就能覆盖；漏标和自定义实现仍需补充。 |
| B | 已知接口、父类、受控实体上的明确查询、基础属性 | 可以覆盖遵循同一契约的模组生物；必须排除装备、药水、当前姿态等临时影响。 |
| C | 生物 ID、生物族标签、明确的模组适配器 | 原版没有可靠的通用声明，或能力依赖专用 AI。以数据配置或专用实现提供。 |

- **全体块**：供体的每个保留体块都可以贡献这项特性，不代表保留一个小块就应让整个成品获得完整效果。
- **头**：供体原本的头部；头与身体相连即可承载认知特性，通常无需脖子关节。
- **躯干、腿、翅、鳍、壳、刺、攻击器官**：供体的解剖角色。腿、臂还需结合装配后的有效关节和承重/攻击用途判断。
- **原始部位与装配用途分开**：把牛躯干接到肩关节不会自动变成毒牙或翅膀；把狼头固定在躯干侧面仍可以承载驯服特性。
- 微小生物可能只有一个模型体块，允许一个体块具有多个角色。不能把“模型未识别出头”解释为“该物种没有头”。

## 一、体质、环境适应和基础防御

| 特性 | 原版来源生物 | 建议承载部位 | 适配方案与限制 |
| --- | --- | --- | --- |
| **抗火／火焰免疫** | 烈焰人、恶魂、岩浆怪、潜影贝、炽足兽、恼鬼、监守者、凋灵、凋灵骷髅、僵尸疣猪兽、僵尸猪灵、末影龙 | **全体块** | **A+B**：先读 `EntityType.fireImmune()`，可补充干净供体的 `Entity.fireImmune()` 覆盖。不要把抗火药水视为先天抗火。不是所有下界生物都抗火，猪灵和疣猪兽不能整族推断。 |
| **遇水受伤** | 末影人、烈焰人、炽足兽、雪傀儡 | **全体块** | **B**：`LivingEntity.isSensitiveToWater()` 是直接入口。成品需处理水、雨和气泡柱，以及水瓶相关行为。必须与普通溺水分开。 |
| **抗冻** | 流浪者、北极熊、雪傀儡、凋灵 | **全体块** | **A**：`minecraft:freeze_immune_entity_types`。不建议直接用一次 `!canFreeze()` 推断先天抗冻：皮革装备与骷髅的转化逻辑会影响结果。 |
| **畏寒／冻结易伤** | 烈焰人、岩浆怪、炽足兽 | **全体块** | **A**：`minecraft:freeze_hurts_extra_types`。原版是冻结伤害额外倍率，不是所有寒冷环境持续扣血；数值可由本模组再平衡。 |
| **阳光灼烧** | 僵尸、僵尸村民、溺尸、骷髅、流浪者、沼骸、幻翼 | **全体块**；遮阳判定另定 | **C**：有实际阳光判定，却没有统一的物种能力标签。建立 `sun_sensitive` 生物族；尸壳排除。不能从 `undead` 推断，亡灵马也不应加入。凋灵骷髅虽经过骷髅类的日照逻辑，但抗火使其不表现为普通日晒灼伤。 |
| **离水窒息／保湿依赖** | 鳕鱼、鲑鱼、热带鱼、河豚、鱿鱼、发光鱿鱼、蝌蚪；美西螈；海豚 | 鱼类可定位头/鳃；保湿依赖定位**全体块** | **C**：至少拆成“离水呼吸失败”和“身体干燥”两项。`WaterAnimal` 只能提示候选：海豚覆盖其空气逻辑且另有湿润度；美西螈有自己的空气计时。海龟、青蛙、守卫者不应只因水生就获得离水伤害。 |
| **高温环境脆弱** | 雪傀儡 | **全体块** | **C**：读取环境时可用原版 `BiomeTags.SNOW_GOLEM_MELTS`，但谁具有这项特性需自行配置。与普通火焰易伤分开。 |
| **治疗／伤害反转** | 所有 `minecraft:undead` 亡灵，详见下方名单 | **全体块** | **A**：`minecraft:inverted_healing_and_harm`；查询入口为 `isInvertedHealAndHarm()`。建议显式设置体质比例门槛，避免一小块僵尸组织反转整只生物。 |
| **免疫中毒** | 亡灵；蜘蛛、洞穴蜘蛛 | **全体块** | **A+C**：亡灵来自 `minecraft:ignores_poison_and_regen`；蜘蛛族是 `canBeAffected` 的专用覆盖。不要把所有节肢生物都当成免毒。 |
| **不接受再生效果** | 亡灵 | **全体块** | **A**：同上标签。必须与免毒分别表示，蜘蛛免毒但不因此拒绝再生。也不等于禁止所有 `heal()` 或食物回血。 |
| **免疫凋零效果** | 凋灵、凋灵骷髅 | **全体块** | **C**：对应类覆盖 `canBeAffected`。定义按效果 ID 的免疫清单，可让其他模组补充。不要把效果免疫与对应伤害类型免疫混为一谈。 |
| **天然护甲** | 僵尸及继承其基础护甲的变种、岩浆怪、凋灵；其他有基础护甲的模组生物 | **全体块**；有明确甲壳者可定位壳 | **B**：读清理后的 `Attributes.ARMOR` 基础值，按实际组织贡献汇总。岩浆怪需要应用稳定的 `Size`。潜影贝闭壳增加的护甲是状态修正，应作为独立壳能力。铁傀儡高血量不等于有天然护甲。 |
| **抗击退** | 铁傀儡、监守者、劫掠兽、疣猪兽、僵尸疣猪兽等 | 躯干与承重腿 | **B**：`Attributes.KNOCKBACK_RESISTANCE` 基础值。可以自动提取数值，但归属部位、承重要求与总值上限由本模组定义，不能直接把多条腿数值相加。 |
| **自然恢复** | 悦灵、马科、凋灵；美西螈有装死期间的条件再生 | 躯干；装死行为额外需要头 | **C**：没有统一的“自然回血速度”属性；这些行为分别在实体 tick 或 Brain 行为中。要分持续恢复、随机恢复、条件再生，尤其不能把美西螈做成常驻回血。 |

本版本 `minecraft:undead` 展开为：僵尸、僵尸村民、尸壳、溺尸、僵尸猪灵、僵尸疣猪兽、僵尸马、骷髅、流浪者、凋灵骷髅、骷髅马、沼骸、凋灵、幻翼。

可选的小众免疫还有：蠹虫的虫蚀免疫（`immune_to_infested`）、史莱姆的渗浆免疫（`immune_to_oozing`）。适合放进通用“状态效果免疫”框架，不必优先设计为独立玩家词条。

## 二、头部、呼吸与交互

| 特性 | 原版来源生物 | 建议承载部位 | 适配方案与限制 |
| --- | --- | --- | --- |
| **水下呼吸／不溺水** | 鳕鱼、鲑鱼、热带鱼、河豚、鱿鱼、发光鱿鱼、蝌蚪、美西螈、青蛙、海龟、守卫者、远古守卫者；所有亡灵 | **头/鳃**；亡灵“不需氧”可由族规则改为全体块 | **A+B**：标签 `minecraft:can_breathe_under_water`。NeoForge 应优先查询 `canDrownInFluidType(NeoForgeMod.WATER_TYPE.value())` 的反值；原版 `canBreatheUnderwater()` 在此版本已是 `final` 且被标为 deprecated。模组流体按各自 `FluidType` 处理。 |
| **长时间屏息** | 海豚 | 头/呼吸系统 | **B+C**：`getMaxAirSupply()` 可以读取容量，但只有空气呼吸物种才能解释成屏息；鱼类和美西螈也使用空气计数器记录离水时间，不能统一套用。海豚不会水下呼吸。 |
| **可驯服并建立主人关系** | 狼、猫、鹦鹉；马、驴、骡、羊驼、行商羊驼 | **头** | **B+C**：`TamableAnimal` 是狼/猫/鹦鹉的良好检测入口；`AbstractHorse` 需专门适配。骆驼不需要驯服，骷髅马/僵尸马不能因继承马类就被标为常规可驯服。继承“可驯服能力”，不复制供体主人和当前已驯服状态。 |
| **信任／合作** | 狐狸、豹猫、悦灵 | **头** | **C**：分别是信任关系、降低对玩家戒备、与给予物品的玩家合作，不等同于宠物驯服。可以统一成较宽的“亲和”上位类别，底层仍保留模式。 |
| **食性／食物识别** | 各种 `Animal`，如牛、羊、猪、鸡、兔、狼、猫等 | 头（进食）；如有消化系统再关联躯干 | **B+C**：`Animal.isFood(ItemStack)` 适合验证一个给定物品是否被视作食物，但不能返回完整食谱，也不代表驯服材料或回血量。优先显式物品标签；按需查询候选物品并缓存。 |
| **性情与认知等级** | 友好、中立、敌对生物；不同生物的认知分级 | **头** | **B+C**：项目已有 `NeutralMob`、`Enemy` 分类和数据覆盖，以及 `BionicMind` 多头汇总。认知等级仍是本模组设定，没有原版通用智力值。沿用既有机制，避免另起一套冲突的判断。 |
| **感知振动／嗅探** | 监守者的振动与嗅探；嗅探兽的植物搜寻 | **头/感知器官** | **C**：可复用事件监听设施，但 `VibrationSystem` 不是“拥有监守者听觉”的充分条件，悦灵也实现它。把感知半径、事件过滤、目标种类作为独立参数；无需附赠声波攻击。 |
| **避水偏好** | 末影人等明确设置水寻路惩罚的生物 | **头** | **B（候选）+C**：`Mob.getPathfindingMalus(PathType.WATER)` 可作提示，但默认值、当前导航和模组实现会影响意义。与“遇水受伤”分开；畏水体质可以另行给成品导航追加避水规则。 |
| **威慑特定生物** | 猫/豹猫对苦力怕的回避关系，猫对幻翼的威慑；狼对骷髅的威慑 | 头；是否需要外形完整由玩法决定 | **C**：关系经常写在“受惊者”的 AI 中，并非供体暴露能力。成品不是 `Cat` 或 `Wolf`，读取成功也不会自动让其他生物害怕它，需要适配对方的目标/回避逻辑。 |

“可骑乘”应独立于“可驯服”：猪、炽足兽、骆驼也能骑乘。骑乘主要是成品躯干尺寸、座位、控制方式和装备槽规则，不建议仅移植一个马头就直接解锁全部骑乘与背包功能。

## 三、运动与地形能力

| 特性 | 原版来源生物 | 建议承载部位 | 适配方案与限制 |
| --- | --- | --- | --- |
| **材料型免疫摔落** | 岩浆怪、铁傀儡、雪傀儡、潜影贝；旋风人可归入特殊身体 | **全体块/核心躯干** | **A 识别+C 分型**：`minecraft:fall_damage_immune` 直接提供结果；为什么免摔、应该给哪个部位，必须自行分类。普通史莱姆不在这个标签中，不应误认为它和岩浆怪都免摔。 |
| **灵巧落地** | 猫、豹猫 | **承重腿** | **A 识别+C 部位**：同一免摔标签，映射成腿部能力。建议要求足够的有效落地腿，区别于材料抗冲击与飞行。 |
| **减轻摔落** | 马科、山羊 | **承重腿** | **B+C**：马科提供 `SAFE_FALL_DISTANCE`、`FALL_DAMAGE_MULTIPLIER`；山羊另在 `calculateFallDamage` 中减少伤害，单读属性会漏掉。支持“安全落差、倍率、固定减伤”分别配置。 |
| **扑翼飞行** | 蜜蜂、鹦鹉、蝙蝠、幻翼、悦灵、恼鬼；末影龙可另作高阶供体 | **翅**，结合身体负载 | **B（候选）+C**：`FlyingAnimal`、`FlyingMob`、导航类型只能部分识别，悦灵和蝙蝠等并不统一走同一接口。需要翼部映射及本模组的飞行控制；`isFlying()` 是当前状态，不是天赋声明。 |
| **缓降** | 鸡；烈焰人下降速度受到限制 | 鸡：**翅**；烈焰人：身体 | **C**：专用运动逻辑。鸡的缓降不应升级成自由飞行；烈焰人的浮空行为也不等同于恶魂全向飞行。 |
| **悬浮／无翼飞行** | 恶魂、凋灵；烈焰人可提供受限升空 | **核心躯干** | **C**：区分持续全向悬浮和条件升空。读取 `isNoGravity()` 不能可靠识别天生飞行，有些实体每 tick 改状态，有些以自定义速度控制实现。 |
| **游泳专长** | 鱼类、鱿鱼类、海豚、海龟、美西螈、守卫者等 | **鳍、尾、触手、水生腿** | **B（候选）+C**：水生标签和导航可辅助分类，但不能直接给出泳速、推力与器官。水下呼吸不代表擅长游泳；不溺水的僵尸也不能自动获得鱼类运动。 |
| **攀墙** | 蜘蛛、洞穴蜘蛛 | **腿** | **C**：蜘蛛使用接触状态、专用寻路和 `onClimbable()`。后者是当前能否攀爬，普通生物站在梯子上也可能为真，不适合天赋检测。支持蜘蛛族标签及显式模组适配。 |
| **蛛网适应** | 蜘蛛、洞穴蜘蛛 | **全体块**，或限定接触腿 | **C**：原版在 `makeStuckInBlock` 中排除蛛网减速；无通用能力字段。不要调用这个修改实体状态的方法作探测。 |
| **跳跃专长** | 兔、山羊、青蛙、史莱姆、岩浆怪；马科为可控制跳跃 | **腿**；史莱姆类为**身体** | **B+C**：基础跳跃属性可以提供数值，但山羊/青蛙长跳和史莱姆弹跳依赖不同控制器。统一成跳跃能力后，保留普通跳、长跳和周期弹跳模式。 |
| **熔岩表面行走** | 炽足兽 | **足/承重腿** | **C**：单独实现流体表面支撑；抗火不会自动提供熔岩行走。混合身体即使能站在熔岩上，也未必全身抗火。 |
| **细雪表面行走** | 兔、狐狸、蠹虫、末影螨 | **足/承重部位** | **A 识别+C 部位**：`minecraft:powder_snow_walkable_mobs`。必须与抗冻分开；穿皮革靴带来的效果也不应遗传。 |

本版本 `fall_damage_immune` 的完整生物名单是：铁傀儡、雪傀儡、潜影贝、悦灵、蝙蝠、蜜蜂、烈焰人、猫、鸡、恶魂、幻翼、岩浆怪、豹猫、鹦鹉、凋灵、旋风人。这个名单是**标签覆盖范围**；其他通过不下落、穿透或自定义运动避免落伤的生物，仍需单独适配，不能据此断言所有未列出的飞行生物都会摔伤。

## 四、可泛化的攻击与器官防御

| 特性 | 原版来源生物 | 建议承载部位 | 适配方案与限制 |
| --- | --- | --- | --- |
| **毒性攻击** | 洞穴蜘蛛、蜜蜂；河豚为接触毒性 | 洞穴蜘蛛：**头/口器**；蜜蜂：**尾刺/腹部**；河豚：**体表刺/身体** | **C**：定义“指定攻击器官命中后施加效果”，不要给所有手臂复制毒性。持续时间、难度条件、触发概率、河豚膨胀条件分别配置；蜜蜂失刺后死亡不必与毒性强绑。 |
| **凋零攻击** | 凋灵骷髅；凋灵为专用远程攻击 | 骷髅：**实际攻击臂/手**；凋灵：头部发射器 | **C**：适配命中后的凋零效果。它和供体免疫凋零是两个独立能力。 |
| **饥饿攻击** | 尸壳 | **实际攻击臂/手** | **C**：保留空手等原版触发条件或显式改成模组规则。饥饿主要影响玩家，对普通生物的用途有限，优先级较低。 |
| **附效远程攻击** | 流浪者的迟缓箭、沼骸的剧毒箭 | **使用远程武器的臂/手** | **C**：需要远程攻击支持和弹射物适配。原版赋效发生在造箭逻辑，不等于它们的徒手攻击也附带效果。 |
| **接触反伤** | 守卫者、远古守卫者；河豚的刺伤可共用部分设施 | **刺/带刺体表** | **C**：守卫者受运动状态、伤害类型与直接攻击者条件限制。伤害处理器要防止反伤互相递归，也不能把一根刺的效果复制到所有命中部位。 |
| **偏转弹射物** | 旋风人 | **身体/风场核心** | **A+C**：`minecraft:deflects_projectiles` 可以识别；`Entity.deflection(Projectile)` 提供执行入口。旋风人的覆盖排除两类风弹，不能粗暴转成所有远程伤害无敌。模组自定义弹射物若不调用原版偏转流程仍需适配。 |
| **缩壳防御** | 潜影贝、犰狳 | **壳/主要躯干** | **C**：潜影贝闭壳护甲和箭矢免疫、犰狳蜷缩减伤是不同状态机制。适合共用“防御姿态”框架，但不能单读自然护甲后永久附赠闭壳收益。 |

这类能力的共同实现可以是“触发事件 + 作用部位 + 条件 + 效果”，但不能自动从其他模组的 `hurt()`、`doHurtTarget()` 或 Brain 中提取任意行为。

## 五、建议的跨模组架构

### 1. 先读取物种事实，再决定器官归属

建议分开三类数据：

| 数据 | 示例 | 生命周期 |
| --- | --- | --- |
| 供体固有事实 | 类型 ID、稳定变种、先天抗火、免摔标签、基础护甲 | 从供体类型/稳定状态解析；按数据版本缓存。 |
| 解剖映射 | 哪些原始体块是头、翅、腿、刺；原始器官完整度 | 随供体模型布局保存和验证，切割只移除保留部分。 |
| 成品能力 | 抗火覆盖率、可驯服、哪条臂附毒、能否飞行 | 每次装配/重载重新计算，运行时由成品执行。 |

默认不遗传：药水、装备及附魔、当前燃烧/冻结、仇恨、已驯服状态、主人 UUID、当前目标、短期属性修正、瞬时无敌、现有乘客和掉落物。稳定的大小、变种、是否有角等可走明确白名单。

查询方法也需要白名单：优先注册信息；必要时在服务端按需构造一个未加入世界的供体实体并应用稳定数据，仅调用经过审查的查询。不要 tick 供体、调用攻击/受伤方法或真的给它施加效果来“试出”能力。实体构造也可能有模组侧副作用，适配器需能拒绝这种探测并返回未知。

### 2. 生物族使用标签，特殊实现使用适配器

建议提供自己的语义族，例如 `create_biotech:spider_like`、`create_biotech:sun_sensitive`、`create_biotech:tameable_equines`。这些是**拟新增标签**，不是现有原版标签。

- 原版已有的能力标签直接复用，避免维护重复名单。
- 族定义尽量表达共享能力，而非仅看外形、名称或 mod ID。
- `Spider`、`TamableAnimal` 等继承关系可以作为内置探测器的提示；模组不继承同一父类时可通过标签补齐。
- 单体规则能新增、移除或调整某一个特性，不必复制整个物种定义。
- 需要读取模组特有基因、能量、器官等字段时，使用显式注册的 Java 适配器；未知模组回退到通用规则。

每项结果建议使用 `present / absent / unknown`，避免把探测失败当作明确没有能力。跨模组适配是“遵循共享契约的自动覆盖”，不是对任意模组实现的完整反推。

### 3. 覆盖优先级必须明确

推荐逐个特性执行以下优先级，而不是按整个供体覆盖：

`自动探测 < 内置/模组适配器 < 生物族规则 < 单个生物规则 < 显式禁用规则`

上述是建议的解析策略，需由本模组实现；不同数据包仍尊重资源包优先级。同级多个族规则通过明确 `priority` 解决，冲突应可诊断，不能依赖 JSON 键顺序。强制移除应保留为禁用记录，不能删除记录后让自动探测重新加回来。

NeoForge 1.21.1 的 **Data Maps** 适合把可重载配置关联到 `EntityType`：支持 ID、标签、重载和可选客户端同步。集合型特性可以采用 `AdvancedDataMapType` 的自定义合并；但“单体总比族高”等语义仍要明确设计，不能假定框架自动符合上述规则。[NeoForge 1.21.1 官方文档](https://docs.neoforged.net/docs/1.21.1/resources/server/datamaps/)

项目也可以继续沿用现有 JSON 重载器，增加独立的族匹配和逐项覆盖阶段。不要仅为这次功能强制迁移现有头部性情配置。

以下只是**拟议业务字段**，不是当前已支持的配置格式：

```json
{
  "match": { "entity_type_tag": "create_biotech:spider_like" },
  "priority": 100,
  "traits": {
    "create_biotech:poison_immunity": {
      "mode": "enable",
      "parts": "all"
    },
    "create_biotech:climbing": {
      "mode": "enable",
      "parts": "source_legs",
      "requires": "functional_support_limbs"
    }
  }
}
```

洞穴蜘蛛再通过单体规则为 `source_head` 添加毒性咬击；某个模组的机械蜘蛛可以单独禁用免毒。这样可以适配族，同时保留个体差异。

### 4. “获得特性”与“成品真正生效”是两套工作

成品是 `SlimeBionicEntity extends PathfinderMob`，不会因为记录了“供体是猫”就执行猫的交互与 AI，也不会因供体属于亡灵而自动继承全部亡灵标签效果。

- **可通过虚方法执行**：抗火、遇水受伤、治疗反转、允许冻结、摔落计算、部分流体行为与弹射物偏转等，在成品上读取解析结果。
- **原版直接查实体类型标签的地方**：不能动态修改共享的 `EntityType` 标签来表示某一只成品。需要针对成品的覆盖、事件钩子，或必要时很小范围的 mixin。
- **驯服、跟随、坐下、攻击主人目标**：成品需要自己的主人数据与行为。仅识别 `TamableAnimal` 不会搬运这些功能。
- **飞行、游泳、攀墙**：需要成品自己的移动控制和寻路切换，不能把供体的 Goal/Brain 对象直接拿来用，它们通常绑定供体实例和专有字段。
- **威慑、附魔种族增伤**：判定可能在外部生物或数据驱动的附魔条件中。若希望部分亡灵组织同时承受亡灵杀手增伤，需要额外桥接，不能承诺从“治疗反转”自动得到完整亡灵兼容。
- **状态效果免疫**：NeoForge 的 `canBeAffected` 被标注为 override-only，框架通过 `CommonHooks.canMobEffectBeApplied` 及事件进行应用判定。适合作为成品的执行入口之一，不建议遍历全部效果并调用事件总线来推断永久生物学特征。末影龙直接覆盖 `addEffect` 也说明单一查询无法穷尽所有实现。

## 六、混合身体的合并规则

| 能力类别 | 建议合并规则 | 理由 |
| --- | --- | --- |
| 组织性抗性、弱点、天然护甲 | 按保留组织的有效体积/质量权重计算；有局部命中信息时按受击部位计算 | 避免切成更多小块增加收益，也避免一点抗火组织保护所有易燃部位。 |
| 头部认知与交互 | 一个足够完整、连通的有效头解锁能力；强度取最大值或选定主头 | 可驯服是一种能力，不需要按所有体块平均。多头仍只保留一套主人关系。 |
| 运动器官 | 器官完整度、有效关节、数量及承重要求共同决定 | 两片悬空猫腿不能使巨型身体完全免摔，飞行应受翼能力与身体负载约束。 |
| 攻击器官 | 只给该器官实际完成的攻击赋效 | 毒牙不能使另一条普通僵尸臂的每次挥击都带毒。 |
| 防御姿态 | 保留足够的壳/躯干，主动进入状态后生效 | 区别于无条件体质，避免永久闭壳或永久蜷缩减伤。 |

第一版没有可靠的局部火焰接触信息时，可以使用明确的近似：抗火覆盖率 `r = 抗火组织权重 / 总组织权重`，火焰伤害乘以 `1-r`；只有完整覆盖才返回整只生物 `fireImmune() == true`。如改用解锁门槛，也应把门槛公开为规则，而不是暗中使用“任意体块取并集”。

水敏感、日照脆弱等负面体质可按组织权重贡献；器官性效果则采用器官完整度。治疗反转等二值效果应选明确门槛或主体体质，不建议对每次效果随机决定。

注意原版水敏感伤害和溺水都可能使用 `drown` 伤害来源。不能通过“取消所有溺水类型伤害”实现水下呼吸，否则烈焰人组织的水敏感可能被意外消除；应在呼吸耗气/呼吸事件层处理。

各特性保留独立性：

- 烈焰人组织可以同时抗火、怕水、冻结易伤。
- 鱼头能提供水下呼吸，不会消除其余末影人组织的遇水伤害。
- 猫腿可以提供落地能力，不会让没有猫头的成品可驯服。
- 蜘蛛腿可以攀墙，毒性需要洞穴蜘蛛口器；普通蜘蛛腿本身不提供毒性攻击。
- 凋灵组织可以拒绝再生药水，却仍具有源码中直接调用 `heal()` 的自然恢复；两者不矛盾。

## 七、与现有工程的衔接

当前已有可复用基础：

- `content/slimemimic/MimicProfile.java`：实体类型、稳定状态白名单、与玩法数据分离的预览快照。
- `content/surgery/SurgicalAssembly.java`：每个 `Source` 保存 profile、保留体块、头部体块、接缝和装配关系。
- `content/surgery/client/SurgicalCapturedRenderPlan.java`：通过模型及 Create 帽子定位数据识别头部体块。
- `entity/ai/BionicDispositionRegistry.java`：通用接口探测、缓存、数据覆盖的既有范例。
- `entity/ai/BionicHeadDataReloadListeners.java`、`BionicMind.java`：数据重载与多头性情/智力汇总。

推荐增量顺序：

1. 先实现“全体块 + 头”的部位作用域、通用特性结果和逐项覆盖。这一层已经可以支持抗火、水敏感、抗冻、水下呼吸、治疗反转和头部可驯服。
2. 接入基础护甲、效果免疫与摔落结果；对不同来源设置明确的部位分配。
3. 增加服务端认可的腿、翅、鳍、壳、刺等解剖角色，以及器官完整度和每体块权重，再做运动和器官攻击。
4. 最后增加专门的飞行导航、缩壳、感知、威慑等行为适配。

现有 `headCubes` 是保留下来的头部集合，足够检测“有没有头部体块”，但不足以单独判断“原头部保留了百分之多少”。器官完整度需要额外保留原始角色集合或原始权重。装配中的 `Source` 拆分也不能让同一器官碎片被重复计为多个独立能力。

客户端目前参与模型体块识别。扩展到决定战斗/免疫的部位映射时，服务端需要可验证的映射/缓存和一致性校验，不能让客户端直接声明自己有任意能力。对 GeckoLib、自定义渲染模型或无法识别部位的供体，回退到已知全体块特性，特殊器官通过资源/数据适配补齐。

特性缓存应按类型、相关稳定变种和数据重载版本建立；不要按含完整预览 NBT 的 profile 无限制扩张。`/reload`、重装配和存档读入时重新解析派生能力；保存来源和规则版本，不把旧规则的最终结果永久写死。

## 八、不建议第一批当作基础体质提取的能力

瞬移、穿墙、自爆、分裂、复制、召唤、感染/转化、村民交易、捡物分类、挤奶、剪毛、产蛋、产蜜、造雪、方块破坏和完整 Boss 技能，更适合独立功能器官或专用行为模块。

其中生产能力可以在后续统一成“器官 + 输入/环境条件 + 产物 + 冷却”，但原版没有一个可自动读取所有生物生产配方的接口。类似地，不能因为一个模组生物拥有某种掉落物，就推断其组织能够主动生产这种物品。

不建议从夜间生成推断夜视、从材质外观推断护甲、从名称推断元素免疫、从免摔直接推断飞行、从 Boss 身份推断所有效果免疫。这些推断都不具备可靠的跨模组语义。
